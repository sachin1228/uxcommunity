# Your Community — Feature Spec

Full spec for the **"Your Community"** feature in drafthub. This is a self-serve community creation and management system that lets any member create their own community inside the platform.

---

## 1. Sidebar Entry Point

**Location:** The existing sidebar, under the `YOUR COMMUNITY` section header.

**Change:** Add a `+` icon button in a small circle (18px) floated to the far right of the `YOUR COMMUNITY` header row.

- Clicking `+` opens the **Create Community modal** (Step 1).
- The button uses `hover` state: border and icon colour lighten on hover.
- Existing community rows in the sidebar remain clickable — they open the **Community Detail** view.

---

## 2. Create Community Flow (3-step modal)

A centered modal (max-width 480px) with a dimmed + blurred backdrop. The modal has a step progress indicator (3 dots at the top, filling left-to-right as the user advances).

### Step 1 — Name & Privacy

**Fields:**
- **Community Name** — text input, placeholder `e.g. Design Systems`. Continue button is disabled until at least 1 character is entered.
- **Privacy** — two large card-style radio buttons stacked vertically:
  - 🌐 **Public** — "Anyone can discover & join"
  - 🔒 **Private** — "Invite-only, you approve members"
  - Selected card gets accent border + accent background tint + accent icon colour.

**Footer:** `[Cancel]` `[Continue →]`  
Cancel closes the modal and returns to Screen 1 (empty state).

---

### Step 2 — Tab Selection

**Heading:** "What's in your community?"  
**Subheading:** "Choose the tabs members will see"

**Four toggle cards in a 2×2 grid:**

| Tab | Icon | Description | Behaviour |
|-----|------|-------------|-----------|
| Chat | MessageSquare | Real-time messaging | **Required** — always selected, non-toggleable. Shows "Required" label. |
| Events | Calendar | Meetups & online events | Optional toggle |
| Threads | Hash | Topic discussions | Optional toggle |
| Resources | BookOpen | Links & files | Optional toggle |

Selected cards: accent border + accent background tint + filled checkbox in corner.  
Unselected cards: default border + hover accent border.

**Footer:** `[← Back]` `[Continue →]`

---

### Step 3a — Public Community (Success screen)

- Large accent checkmark circle illustration
- Heading: "Your community is live!"
- Body: Community name shown in accent colour + "Members can now find and join via the Discover page."
- Button: `[Open Community →]` → navigates to **Community Detail** view

---

### Step 3b — Private Community (Invite Link screen)

- Heading: "Invite your first members"
- **Invite link row:** read-only text input showing `drafthub.co/join/{slug}-{token}` + `[Copy Link]` button
  - Copy button briefly changes to `[✓ Copied!]` (2 seconds) then resets
- **Helper text:** "Anyone with this link can request to join. You'll approve each request."
- **QR code placeholder:** 80×80px dashed box labelled "QR" (actual QR generation is out of scope for now)
- Button: `[Done →]` → navigates to **Community Detail** view

---

## 3. Community Detail View

Full right-panel view (replaces the empty state). Reached by:
- Completing the creation flow (Step 3 → "Open Community" / "Done")
- Clicking any community row in the sidebar

### Header

- `[← back arrow]` — returns to the empty state (Screen 1)
- Community avatar circle (first letter of name, accent background)
- Community name + 🔒 lock icon if private
- Member count badge (e.g. "4 members")
- `[⚙ Settings]` button — opens the **Settings** view

### Tabs bar

Tabs shown are determined by the selection made in Step 2 (always includes Chat). Active tab has an accent underline. **Members tab is always present** regardless of tab selection.

| Tab | Notes |
|-----|-------|
| Chat | Always present |
| Threads | Shown if selected in Step 2 |
| Events | Shown if selected in Step 2 |
| Resources | Shown if selected in Step 2 |
| Members | Always present |

### Members Tab (default active on first open)

**Section A — Members list**

Each row:
- Avatar (coloured circle with initials) + Name + join date + role badge
- **Owner** row: shows `OWNER` badge (accent colour), no action menu
- **Member** rows: `···` (MoreHorizontal) button → dropdown with `[Remove from community]` in red
  - Clicking Remove immediately removes the row from the list

**Section B — Pending Requests** *(Private communities only, shown above Members list)*

Shown when the community is private and there are pending join requests.

Each row:
- Avatar + Name + "Requested to join Xh ago"
- `[✓ Accept]` green button — removes from Pending, adds to Members list, shows toast "Member added" (3 seconds)
- `[✗ Decline]` muted button — removes from Pending only

## 4. Community Settings

Opened via `[⚙ Settings]` button in the Community Detail header. Full right-panel view (replaces the community content area).

### Header

- `[← back arrow]` — returns to Community Detail (without saving)
- Title: "Community Settings" + community name as subtitle
- `[💾 Save changes]` button — saves all changes and returns to Community Detail with a "Settings saved" toast

### Sections

#### General
- **Community Name** — editable text input, pre-filled with current name
- **Description** — optional multi-line textarea, placeholder "What's this community about?"

#### Privacy
- Two card-style radio buttons (same style as Step 1): Public / Private
- Pre-selected to the community's current privacy setting
- Checkmark icon appears on the active card

#### Tabs
- Four cards in a 2×2 grid (same as Step 2)
- Pre-checked to reflect which tabs are currently enabled
- Chat card is locked ("Required"), others toggle freely

#### Rules
- Section header: "Rules" with "Members see these before joining" subheading
- `[+ Add rule]` link in the header row (accent colour)
- Rules displayed as a numbered list in a bordered card
- Each rule row: number badge + rule text + ✕ remove button (visible on row hover)
- Clicking `[+ Add rule]` opens an inline input row at the bottom of the list:
  - Text input with accent border (autofocused)
  - `[Add]` button — appends the rule to the list
  - `[Cancel]` button — dismisses without saving
  - Pressing Enter also adds the rule; Escape cancels

#### Invite Link
- Always visible (for both public and private communities)
- For **private**: shows "Private" badge + "Members must request via this link. You approve each request."
- For **public**: "Share this link to bring members directly to your community."
- Read-only input showing `drafthub.co/join/{slug}-{token}` (monospace font)
- `[Copy]` button → changes to `[✓ Copied!]` briefly
- `[↺ Regenerate link]` text button below — changes the token in the URL + shows "Link regenerated — old link is now invalid" confirmation text

#### Danger Zone
- Red-tinted section header
- Row: "Delete this community" + description + `[🗑 Delete]` red-bordered button
- Clicking Delete opens a **confirmation overlay** (not a separate page):
  - Warning icon + "Delete community?" heading
  - Body text naming the community + "This action cannot be undone."
  - `[Cancel]` — dismisses overlay
  - `[🗑 Delete]` red — deletes community, navigates to empty state (Screen 1)

## 6. State & Data Model

### New database tables needed

```sql
-- communities (user-created)
CREATE TABLE user_communities (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  description text,
  type text NOT NULL DEFAULT 'user', -- distinguish from admin-created communities
  is_private boolean NOT NULL DEFAULT false,
  owner_id uuid NOT NULL REFERENCES designer_profiles(id),
  invite_token text NOT NULL DEFAULT gen_random_uuid(),
  tabs text[] NOT NULL DEFAULT ARRAY['chat'],
  rules text[] NOT NULL DEFAULT ARRAY[]::text[],
  member_count integer NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now()
);

-- membership
CREATE TABLE user_community_members (
  community_id uuid NOT NULL REFERENCES user_communities(id) ON DELETE CASCADE,
  user_id uuid NOT NULL REFERENCES designer_profiles(id),
  role text NOT NULL DEFAULT 'member', -- 'owner' | 'member'
  joined_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (community_id, user_id)
);

-- join requests (private communities only)
CREATE TABLE user_community_requests (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  community_id uuid NOT NULL REFERENCES user_communities(id) ON DELETE CASCADE,
  user_id uuid NOT NULL REFERENCES designer_profiles(id),
  status text NOT NULL DEFAULT 'pending', -- 'pending' | 'accepted' | 'declined'
  requested_at timestamptz NOT NULL DEFAULT now()
);
```

### Invite link URL pattern

`/join/{community_id}?token={invite_token}`

- Public: invite link skips the request step, joins directly
- Private: invite link creates a `user_community_requests` row with status `pending`

## 7. API Routes Needed

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/communities/create` | Create a new community |
| GET | `/api/communities/mine` | List communities the user owns |
| GET | `/api/communities/:id` | Get community detail + members |
| PATCH | `/api/communities/:id` | Update name, description, privacy, tabs, rules |
| DELETE | `/api/communities/:id` | Delete community (owner only) |
| POST | `/api/communities/:id/join` | Join (public) or request to join (private) via invite link |
| GET | `/api/communities/:id/requests` | List pending join requests (owner only) |
| POST | `/api/communities/:id/requests/:requestId/accept` | Accept a join request |
| POST | `/api/communities/:id/requests/:requestId/decline` | Decline a join request |
| DELETE | `/api/communities/:id/members/:userId` | Remove a member (owner only) |
| POST | `/api/communities/:id/invite/regenerate` | Regenerate invite token |

## 8. Out of Scope (for this iteration)

- Actual QR code generation (placeholder shown)
- Multiple admins / co-owners
- Community image / cover photo upload
- Pinned messages or announcements
- Community discovery / search page
- Notifications for join requests
- Member roles beyond Owner / Member
