## What

Redesigns media delivery to use Cloudflare's CDN edge cache with R2 as the origin, and fixes the media lifecycle so orphaned R2 objects are deleted when their owning entity is deleted (or replaced/abandoned).

## Part 1 — Media caching architecture

- **R2 stays the origin** (single media bucket, configured via `R2_BUCKET_NAME`; prod = `drafthub`). No duplicate cache bucket, no Cache Reserve.
- **Every upload is now tagged `Cache-Control: public, max-age=31536000, immutable`** (`lib/r2.ts` + the city-image script). All object keys are versioned (timestamp/random/UUID), so immutable caching is safe — a URL never changes content.
- **Requires a manual dashboard step**: `R2_PUBLIC_URL` must be a custom domain attached to the bucket (e.g. `media.uxcommunity.in`), not the `pub-*.r2.dev` dev URL — r2.dev responses bypass the CDN edge cache. Documented in `wrangler.toml`, `.env.example`, `INFRASTRUCTURE-AUDIT.md`.
- Videos/audio/PDFs/images are served directly from the R2 domain; HTTP Range/`206` pass straight through, so seeking/scrubbing/resume/mobile playback are untouched. The Next.js worker only proxies media for the save-to-disk helper (`/api/image-download`), unchanged.
- **`uxcommunity-web-next-cache` is kept** — it is the OpenNext incremental cache (ISR / unstable_cache) and is required; it is a different bucket from the media bucket.

## Part 2–4 — Media lifecycle fixes

New shared module `apps/web/lib/r2-cleanup.ts` — a single source of truth for every media-referencing column (`ALL_MEDIA_LOOKUPS`), used by both runtime deletion and the orphan audit so they can never disagree.

**Hard-delete paths that previously leaked R2 objects (now clean up, with shared-media protection):**
- Admin community delete (image, lottie, chat images, thread attachments, showcase images/videos/posters, event covers, community-scoped lottie_settings)
- Last-member-leaves community delete
- Admin user delete (avatar)
- Admin message delete + bulk message reset (images)
- Admin lottie-settings delete (lottie objects)
- Admin master-data deletes (city/sector/interest/experience-level: master images/lottie + all linked communities' media)

**Replaced/removed media fixes:**
- Community picture removal (`remove_image`) now deletes the old object
- Event cover removed (`cover_image_url: null`) now deletes the old object
- Thread PATCH now selects `attachments` — previously the old attachment URLs were never cleaned on edit (silent bug)
- Event PATCH now selects `cover_image_url` — previously the old cover was never cleaned on replace (silent bug)
- Master-data image re-fetch deletes the replaced image when unreferenced

**Failed/abandoned upload cleanup:**
- Community create, community display-picture save, showcase poster, and master-data image fetch now delete their upload when the DB step fails
- Standalone upload endpoints (chat/thread/event/showcase) are covered by the orphan sweep below

## Part 5 — Orphan detection & safe cleanup

`/api/admin/r2-audit` (Admin → Tools → R2 storage health) upgraded:

- Reference tracking now includes **showcase attachments + video posters and `lottie_settings`** — previously those were invisible to the audit, so `delete-orphans` could have deleted live showcase videos.
- Orphan reports include object **size, last-modified, and age**; storage totals are real.
- `delete-orphans` now enforces a **7-day grace period** by default (objects of unknown age are never deleted; `force: true` bypasses only the age check — the DB reference re-check always applies), so in-flight uploads and signup-pending avatars are safe.

## Notes

- Deletion is retry-safe/idempotent: R2 delete of a missing key is a no-op; any object that survives a failed cleanup is caught by the next orphan scan after the grace period.
- Deleted-object edge copies can linger up to the immutable max-age (1 year); keys are unguessable and content is public-by-design, so no per-object purge is issued. Time-sensitive removals can be purged via the Cloudflare API.
- No database migration and no new Worker/cron/queue — the existing admin-triggered scan is the cleanup mechanism.
- Verified: `tsc` adds no new errors (739 baseline `never`-inference errors remain, all pre-existing and ignored by the build), ESLint clean on all changed files, 7/7 r2-lifecycle unit tests pass, `next build` passes.
