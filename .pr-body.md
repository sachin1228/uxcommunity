## What

The homepage right rail restated the left sidebar — *Explore communities*, *Saved resources*, *Find UX jobs*, *Your profile* and *Start a community* all already live in the global sidebar, so the rail spent 288px repeating navigation the member could already see.

It now carries only what the left sidebar does not: **which posts the community is loving this week**, and **which communities are worth joining**.

### Trending Posts

The week's most engaging public posts in rank order, each one linking to the post itself and showing the real like and comment counts.

- **Ranking** — `score = (likes + comments) × 0.5 ^ (age in hours / 72)`. Likes and comments count the same, because a post that started a discussion is at least as interesting as a tapped heart. The age fade is what keeps the card *trending* rather than *all-time*: a post from six days ago needs roughly four times the engagement of one from today to hold its place, so the list keeps moving instead of freezing on one early hit for the rest of the window. The score itself is never shown — the row prints the raw counts, so every number a member reads is one they can account for.
- **Window** — the last 7 days, stated in the card's subtitle.
- **No fake rows** — posts nobody has liked or commented on are skipped; the card says so in its empty state instead of padding the list.
- `lib/home/trending.ts` — pure `engagementOf` / `trendingScore` / `rankTrendingPosts`, unit tested (ordering, the half-life, ties, unparseable timestamps, negative counts, limits).
- Reads the same visibility flag the homepage feed uses (`is_public = true`), so the card can never surface a post its own community would not show.

### Suggested Communities

Open communities the member is not in yet, biggest first, each with a one-tap **Join**.

- `lib/home/suggested.ts` — pure selection, unit tested. Excludes communities the member is already in, ones their profile cannot join, private ones (a "Join" tap there only files a request) and the profile-derived types (city / sector / experience / job title / general), which are auto-joined at signup and are never a discovery.
- Join reuses `POST /api/communities/[id]/join` and `invalidateOnJoin`, so the row disappears optimistically and the left sidebar picks the community up in the same frame, with a rollback and the server's reason if the write fails.

### How it loads

Both lists are loaded on the server (`lib/home/home-sidebar-server.ts`) and slotted into the homepage shell via `HomeRail`, so the rail paints with the page instead of flashing in from a client fetch.

- Trending is one request: PostgREST aggregates the engagement per post in the database (`thread_likes(count)`, `thread_comments(count)`), so the read stays one row per post no matter how many people liked it. The counts are cached for 2 minutes and shared across the whole deployment; the **ranking is recomputed on every render**, so the age fade is always applied against the current clock rather than frozen inside a cache entry.
- Suggestions are cached per member for 60 seconds, and `POST /api/communities/[id]/join` calls `revalidateTag(SUGGESTED_COMMUNITIES_TAG)` so nobody is ever offered a community they just joined.
- The public thread / showcase / resource / event detail pages rendered the same sidebar, so they now share the new rail through that one async entry point.

## Note on the current data

The trend is honest, so the card is only as full as the week is. The candidate set is public posts (`is_public = true`), which is the same shape the homepage feed uses, and at the time of writing the database holds very few of them — so expect a short list until more members post publicly. Members who have joined every matching community see a short empty state in the suggestions card.
