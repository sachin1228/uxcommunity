## What

The homepage right rail restated the left sidebar — *Explore communities*, *Saved resources*, *Find UX jobs*, *Your profile* and *Start a community* all already live in the global sidebar, so the rail spent 288px repeating navigation the member could already see.

It now carries only what the left sidebar does not: **what members are posting about**, and **which communities are worth joining**.

### Trending Topics

Ranks the tags attached to public threads from the last 7 days — `01 Design Systems · 41 Posts · 18.4%`. A topic *is* a thread tag, so there is no second taxonomy to seed or keep in sync with what members actually write. The percentage is each topic's share of the week's tagged threads.

- `lib/home/trending.ts` — pure ranking (case-insensitive grouping, one post counts once per topic, newest spelling wins the label). Unit tested.
- Reads the same visibility flag the homepage feed uses (`is_public = true`), so the card can never surface a thread its own community would not show.
- Built once per deployment for 5 minutes, not per page view.

### Suggested Communities

Open communities the member is not in yet, biggest first, each with a one-tap **Join**.

- `lib/home/suggested.ts` — pure selection, unit tested. Excludes communities the member is already in, ones their profile cannot join, private ones (a "Join" tap there only files a request) and the profile-derived types (city / sector / experience / job title / general), which are auto-joined at signup and are never a discovery.
- Join reuses `POST /api/communities/[id]/join` and `invalidateOnJoin`, so the row disappears optimistically and the left sidebar picks the community up in the same frame, with a rollback and the server's reason if the write fails.

### How it loads

Both lists are loaded on the server (`lib/home/home-sidebar-server.ts`) and slotted into the homepage shell via `HomeRail`, so the rail paints with the page instead of flashing in from a client fetch. `unstable_cache` backs both: trending globally for 5 minutes, and the per-member suggestion list for 60 seconds — `POST /api/communities/[id]/join` calls `revalidateTag(SUGGESTED_COMMUNITIES_TAG)` so nobody is ever offered a community they just joined.

The public thread / showcase / resource / event detail pages rendered the same sidebar, so they now share the new rail through that one async entry point.

No database migration and no new API route — trending reads `community_threads.tags` and suggestions reuse the Explore page's existing `get_all_communities` RPC, so join eligibility is still decided in exactly one place.

## Not included

Members who have joined every matching community see a short empty state rather than an empty card; the trending card says the same when no thread has been tagged in the window.
